One-time setup · api.slack.com

Creating the Slack app

Done once, by us, forever. Every user then connects with a single click and never sees any of this. Budget fifteen minutes. The only thing to send back at the end is the Client ID.

Read this first

Order matters. PKCE must be enabled before you add the http://localhost redirect URLs. Slack historically rejected non-HTTPS redirect URLs outright; localhost is only accepted once the app is marked a public client, which is what enabling PKCE does. Add the URLs first and they will be refused, with an error that does not explain why. Steps below are in the order that works.

1

Create the app, then paste the manifest

api.slack.com/apps→Create New App→From scratch→name it→Create App

From scratch, not From a manifest — the manifest route ends in a Create and Install dialog that installs the app into the workspace, and that step fails for this app (see the note below). Creating from scratch registers the app without installing anything.

app settings→App Manifest→replace the YAML→Save Changes

The manifest still does the useful part: all twelve scopes in one paste instead of twelve dropdown selections.

display_information:
  name: Private Secretary
  description: Local assistant that drafts replies from your messages
  background_color: "#2563eb"
oauth_config:
  scopes:
    # user scopes only — the engine reads and sends AS the user.
    # Do NOT add a bot section: desktop redirects forbid bot scopes.
    user:
      - channels:history
      - groups:history
      - im:history
      - mpim:history
      - channels:read
      - groups:read
      - im:read
      - mpim:read
      - users:read
      - users.profile:read
      - chat:write
      - files:read
settings:
  org_deploy_enabled: false
  socket_mode_enabled: false
Note

No redirect_urls in this manifest on purpose — they go in at step 3, after PKCE is on. The app name here is what every user reads on the consent screen, so it is worth getting right now.

“Installation was not completed”

If you took the manifest route and hit this on Create and Install, ignore it — the app does not need to be installed. The Client ID exists the moment the app record does, and real installs happen through our own OAuth flow on each user's machine, never through this button. Check api.slack.com/apps: if the app is listed, go straight to step 2.

Two likely causes, neither worth fighting. The workspace may require admin approval for app installs, or you may not be an admin there — try a workspace you own, since for a distributed app the home workspace does not matter. Or: this app has zero bot scopes (“What it can respond to in Slack (0)”), and the console's install path expects a bot to install. Nothing to install is not a failure here.

2

Enable PKCE

app settings→OAuth & Permissions→the PKCE setting

This marks the app a public client: the token exchange stops requiring a client_secret, which is what lets the whole flow run on the user's machine with no server of ours anywhere in it.

Irreversible

Slack: “Enabling PKCE marks your app as a public client. This is a one-way operation; it cannot be undone without contacting Slack support.” It is the right call for a desktop product — just make it deliberately, not by clicking through.

3

Add the three redirect URLs

OAuth & Permissions→Redirect URLs→Add New Redirect URL→Save URLs

All three, exactly as written. Slack matches redirect_uri against registered URLs, so an unregistered port simply fails — unlike Google's loopback, which accepts any port. Three ports because a user's 4318 may already be taken by something else.

http://localhost:4318/slack/callback http://localhost:4319/slack/callback http://localhost:4320/slack/callback
If rejected

An error here means step 2 did not take effect. Go back, confirm PKCE is on, reload the page, and try again. Do not switch to https or reach for ngrok — a tunnel would put a third-party host in the callback path, which is the exact property this design exists to avoid.

4

Verify the scopes landed

OAuth & Permissions→Scopes→User Token Scopes

Confirm twelve entries under User Token Scopes, and that Bot Token Scopes is empty. A stray bot scope breaks the desktop redirect at the authorize step with an unhelpful error.

channels:historygroups:historyim:history mpim:historychannels:readgroups:read im:readmpim:readusers:read users.profile:readchat:writefiles:read
5

Turn on public distribution

Manage Distribution→Share Your App with Other Workspaces→Activate Public Distribution

Without this the app installs only into the Taiv workspace, and every outside user gets an error. Slack shows a checklist that must be green first — the redirect URLs from step 3 satisfy most of it.

Not needed

App Directory listing is a separate submission with its own review. It only buys discoverability inside Slack's directory. Installing by link works without it, so skip it for now.

6

Copy the Client ID

Basic Information→App Credentials→Client ID

Looks like 1234567890123.9876543210987. This is the only value needed — it gets committed to the repo as SLACK_CLIENT_ID.

Do not send

The Client Secret, signing secret and verification token stay in the Slack console. PKCE never uses them, and none of them belong in a public repository. If a secret ever does get committed, rotate it in App Credentials rather than just deleting the line.

Verifying it works

Once the Client ID is in place, one command runs the real flow end to end — browser opens, click Allow, token lands in Keychain:

npx tsx scripts/auth/slack-oauth.ts consent
npx tsx scripts/auth/slack-oauth.ts show      # scopes + expiry of what got stored
npx tsx scripts/smoke-slack-direct.ts         # lists your DM channels using it

When something goes wrong

SymptomCause
Redirect URL rejected on save PKCE not enabled yet — step 2 before step 3
invalid_scope at authorize A bot scope is present. Desktop redirects may request user scopes only
bad_redirect_uri The port in use is not one of the three registered, or the path is not /slack/callback
Browser opens, callback never arrives All three ports busy. The consent script says which; free one and rerun
“Installation was not completed” on Create and Install Not a blocker — the app needs no install. Confirm it exists at api.slack.com/apps and carry on from step 2
Works for you, fails for an outside workspace Public distribution not activated (step 5)
User's Allow click needs approval That workspace requires admin approval for app installs. Not something we control — the UI has to explain the wait
