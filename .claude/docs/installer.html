macOS only gate OSTYPE check

The 24/7 residency is built on launchd, which is macOS-only. Rather than half-work on Linux, the script stops immediately with a pointer to manual install. set -euo pipefail is on from the first line: any failed command anywhere aborts the whole run instead of leaving a half-installed system.

Environment self-check [1/4]from OpenClaw

Handles machines in any state — fresh Mac, old Node, no brew — without asking the user to prepare anything. Three ideas taken straight from OpenClaw's installer:

PATH seeding for non-login shells

curl | bash never reads .zprofile, so Homebrew's bin dirs (/opt/homebrew/bin, /usr/local/bin) are prepended manually — otherwise a machine that has Node looks like one that doesn't.

Lazy Homebrew

Homebrew is installed only when something actually needs it (missing Git or Node). Users who already have everything never touch brew.

Git + Node ≥ 20, then verify the winner

Installs or upgrades via brew, runs hash -r to drop the shell's command cache, then re-checks that the Node actually resolved on PATH is new enough — an old Node earlier in PATH fails loudly with a fix instruction instead of silently breaking the build later.

View source 
# Seed Homebrew's bin dirs for non-login curl|bash shells.
for p in /opt/homebrew/bin /usr/local/bin; do
    [[ -d "$p" ]] && [[ ":$PATH:" != *":$p:"* ]] && PATH="$p:$PATH"
done

node_major() { node -v 2>/dev/null | sed -E 's/^v([0-9]+).*/\1/'; }

# Lazy Homebrew — only when git or node actually needs it.
install_homebrew() {
    if command -v brew >/dev/null; then return 0; fi
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
    for p in /opt/homebrew/bin /usr/local/bin; do
        [[ -x "$p/brew" ]] && eval "$("$p/brew shellenv)"
    done
}

if ! command -v git >/dev/null; then
    install_homebrew
    brew install git || abort "git install failed"
fi

if command -v node >/dev/null && [[ "$(node_major)" -ge "$NODE_MIN_MAJOR" ]]; then
    ui_success "Node.js: $(node -v)"
else
    install_homebrew
    brew install node || abort "Node.js install failed"
    brew link node --overwrite --force 2>/dev/null || true
    hash -r
    [[ "$(node_major)" -ge "$NODE_MIN_MAJOR" ]] \
        || abort "Node.js still below v${NODE_MIN_MAJOR}" \
                 "Fix your PATH so the Homebrew node comes first, then re-run."
fi

Clone / update + build [2/4]ours

Lands the code at ~/private-secretary (override with PRIVATE_SECRETARY_HOME) and makes it runnable.

Idempotent checkout

Existing clean checkout → git pull --ff-only. Dirty checkout → warn and keep the user's changes, never overwrite. A non-git directory at that path aborts with instructions instead of deleting anything.

npm install + cockpit:build

The cockpit server serves a prebuilt static bundle — without a build at install time the first page load shows the "run npm run cockpit:build" hint instead of the app.

View source 
REPO_URL="${PRIVATE_SECRETARY_REPO:-https://github.com/LeoTaivDev/private-secretary.git}"
INSTALL_DIR="${PRIVATE_SECRETARY_HOME:-$HOME/private-secretary}"

if [[ -d "$INSTALL_DIR/.git" ]]; then
    # Update: never clobber a dirty checkout.
    if [[ -n "$(git -C "$INSTALL_DIR" status --porcelain)" ]]; then
        ui_warn "Local changes present — skipping git pull"
    else
        git -C "$INSTALL_DIR" pull --ff-only
    fi
elif [[ -e "$INSTALL_DIR" ]]; then
    abort "$INSTALL_DIR exists but is not a git checkout"
else
    git clone "$REPO_URL" "$INSTALL_DIR" || abort "git clone failed: $REPO_URL" \
        "Check network/GitHub access, or override: PRIVATE_SECRETARY_REPO=<url>"
fi

cd "$INSTALL_DIR"
npm install --no-fund --no-audit
npm run cockpit:build   # cockpit serves a PREBUILT bundle

24/7 daemon + cockpit via launchd [3/5]ours

Delegates to the existing scripts/launchagent/install.sh, which renders two plists into ~/Library/LaunchAgents and loads them:

tv.taiv.secretary → run-notify.ts · KeepAlive + RunAtLoad tv.taiv.secretary.cockpit → run-cockpit.ts · 127.0.0.1:4317

Logs live outside TCC-protected folders

Stdout/stderr go to ~/Library/Logs/taiv-secretary/ — never ~/Documents. launchd opens log paths before exec; under a protected folder the spawn fails with EX_CONFIG and zero output (we once had a daemon silently dead for 9 days and 56,484 retries because of this).

View source 
bash scripts/launchagent/install.sh

# ── inside scripts/launchagent/install.sh ──
LOG_DIR="${HOME}/Library/Logs/taiv-secretary"  # outside TCC-protected dirs

install_agent() {
    local label="$1"
    local dst="${HOME_DIR}/Library/LaunchAgents/${label}.plist"
    # Idempotent: unload an already-loaded agent before reloading.
    if launchctl print "gui/$(id -u)/${label}" >/dev/null 2>&1; then
        launchctl unload "$dst" 2>/dev/null || true
    fi
    sed -e "s|@REPO_ROOT@|${REPO_ROOT}|g" \
        -e "s|@NPX_PATH@|${NPX_PATH}|g" \
        -e "s|@LOG_DIR@|${LOG_DIR}|g" \
        "$src" > "$dst"
    launchctl load "$dst"
}
install_agent "tv.taiv.secretary"          # scan daemon
install_agent "tv.taiv.secretary.cockpit" # UI on :4317

Link Claude Code skills [4/5]ours

The runtime is a Claude Code skill (/relay), but skills live in the repo's .claude/skills/ — a fresh user's Claude Code can't see them. Each skill directory is symlinked into the user-level ~/.claude/skills/.

✓ already linked to this checkout → skip ✓ re-run safe — second run links 0 ✗ user's own same-named dir → warn, never touch

Claude CLI probe

If claude isn't on PATH, the user is told where to get Claude Code — the skills are useless without it.

View source 
CLAUDE_SKILLS_DIR="$HOME/.claude/skills"
mkdir -p "$CLAUDE_SKILLS_DIR"
linked=0
for skill_dir in "$INSTALL_DIR/.claude/skills"/*/; do
    name="$(basename "$skill_dir")"
    target="$CLAUDE_SKILLS_DIR/$name"
    # Already linked to THIS checkout → skip (idempotent).
    if [[ -L "$target" && "$(readlink "$target")" == "${skill_dir%/}" ]]; then continue; fi
    # User's own same-named dir → warn, never touch.
    if [[ -e "$target" && ! -L "$target" ]]; then
        ui_warn "~/.claude/skills/$name exists (not ours) — leaving it untouched"
        continue
    fi
    ln -sfn "${skill_dir%/}" "$target"
    linked=$((linked + 1))
done
if ! command -v claude >/dev/null; then
    ui_warn "Claude Code CLI not on PATH — /relay only runs inside Claude Code."
fi

Probes http://127.0.0.1:4317/ after a 2s grace period for launchd to spawn the cockpit. Success prints the URL, log paths, and the next action (open cockpit → Connections, link Slack / Gmail / Jira). Failure isn't fatal — it prints the exact tail -F command to diagnose with.

🔄 Idempotent by design

Every stage is safe to re-run: pull latest, rebuild, reload agents, re-link what's missing. "Re-run the installer" is the upgrade path — there is no separate updater.

🛡 Touch only what's ours

Writes are confined to the checkout dir, two launchd plists, and our own symlinks under ~/.claude/skills. User files, dirty checkouts, and foreign skill directories are warned about and left alone. Any failure aborts immediately with a concrete fix.
